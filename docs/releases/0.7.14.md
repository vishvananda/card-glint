# card-glint 0.7.14

Adds printed color indicators to the Magic pack, with type-text space reserved
before fitting. Scryfall and MTGJSON adapters preserve face-specific indicator
data and distinguish Oracle data from the physical printing. Historical imports
can supply an explicit printing date or reviewed per-face overrides.

Applications can show a current-color badge without changing the card's frame
or mana cost. Set `currentColors`; the default `current-if-changed` policy shows
a badge when these differ from base colors. Without current colors, it shows the
physical printing's indicator. Set `colorIndicatorDisplay: 'printed'` to suppress
current-color changes. Mana cost and frame color alone never trigger a badge. See the [color-indicator guide](../../games/magic/docs/color-indicators.md)
for inputs, multicolor badges, colorless state and composite-face handling.

Indicator assets and multicolor composites are prepared through bounded caches,
including worker composition. Movement does not decode images or regenerate
badges. Semantic hit regions identify each visible indicator. Scan inputs that
need a changed badge rebuild from illustration data rather than silently
modifying a scanned face.

Existing inputs remain compatible. Default controls cover 28 layouts at three
sizes (84 exact comparisons), plus the existing 870 native-host geometry and
pixel probes. Eleven full-face indicator cases match between browser and worker
composition, in source and built packages. Artwork-only inputs retain their
existing per-realm pixels and cache keys. Historical calibration guards remain
exact; this release does not approve blanket score reuse or change calibration
values, finish shaders or the game-neutral API.
