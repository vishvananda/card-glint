# card-glint 0.6.0

Hosts can now sample finishes through texture arrays, compose Magic faces in
workers, paint native intermediate sizes and upload prepared R8 masks directly.

- `foilShader({sampling: 'host'})` and `GLINT_HOST_SAMPLING` use host sampling
  functions with flat instance parameters and explicit face pixel dimensions.
- Battle fronts use the boxed artwork aperture consistently for painting, masks
  and host geometry, and display the reverse creature’s P/T separately from defense.
- Worker Canvas2D composition supports host ImageBitmap/font hooks, etching and
  custom painters, returning transferable ImageBitmap or bottom-up R8 bytes.
- Compose at 244, 488 or 732 pixels, or any bounded integer width, without a
  high-resolution raster followed by downscaling.
- Print periods now use a fixed 732px reference width. Keep the same period at
  every tier; `printDotPeriodForWidth` exposes the corresponding face-texel size.
- `FinishResources.documentMaskData` returns owned, linear R8 bytes without an
  intermediate Canvas snapshot or row flip. Existing image mask output remains.
- Printing-cache pressure keeps the active working set and falls back to the
  procedural shader for overflow. Warm frames no longer repeatedly rebuild the
  same printing. Uniform locations and immutable artwork bounds are reused.

This is a minor release because it adds host contracts and changes public raster
return types to include ImageBitmap. Browser composition still returns a canvas
by default; worker composition returns a bitmap. Narrow the return type before
calling Canvas-only methods, or use `closeRaster` for either result. Existing
uniform shader mode remains available. The print-period migration changes the
appearance of settings previously expressed in source pixels below 732px.

See [host integration](../host-integration.md) for the bindings, worker ownership,
mask upload and migration examples, and [performance](../performance.md) for
benchmark scope and the limits of software-GPU measurements.
